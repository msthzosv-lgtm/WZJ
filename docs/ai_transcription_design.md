# AI 驱动扒谱（音频转 MIDI）软件设计方案

## 1. 目标与成功标准

### 1.1 产品目标
做一个**图形化桌面/Web 应用**，用户上传音频后，系统自动输出 MIDI（可试听、可编辑、可导出）。

### 1.2 精度目标（你提到的 70%~80%）
- **单旋律（人声、独奏）**：音符级 F1 达到 0.80 左右可行。
- **和弦/多声部（钢琴、乐队混音）**：音符级 F1 达到 0.70~0.78 可行。
- **复杂现场录音**：一般会更低，需先做分轨/降噪。

> 结论：你说的“七八十准确度”是现实可达的，但要区分场景和评价指标。

---

## 2. 用户流程（GUI）

1. 进入首页 → 拖拽上传音频（mp3/wav/flac）
2. 选择模式：
   - 快速模式（更快）
   - 高精模式（更准）
   - 旋律模式 / 和弦模式 / 鼓点模式
3. 点击“开始扒谱”
4. 查看结果：
   - Piano Roll 视图
   - 音符列表（起止时间、音高、力度）
   - 速度/BPM、拍号检测结果
5. 手动修正（吸附到节拍、批量量化、移调）
6. 导出：MIDI / MusicXML / JSON

---

## 3. 系统架构（建议）

## 3.1 前端
- 技术：Electron + React（桌面）或 Next.js（Web）
- 核心模块：
  - 上传与任务管理
  - 波形预览（wavesurfer.js）
  - Piano Roll 编辑器（自研 Canvas 或第三方）
  - 导出与工程保存

## 3.2 后端
- Python FastAPI（推理服务）
- 任务队列：Celery / RQ（可选）
- 音频处理：ffmpeg + librosa
- 模型推理：PyTorch / ONNX Runtime
- 存储：
  - 本地版：SQLite + 本地文件
  - 云端版：PostgreSQL + 对象存储

## 3.3 AI 推理流水线
1. 音频预处理（重采样、单声道、响度归一）
2. 节拍/速度检测（BPM & downbeat）
3. 分轨（可选：人声/伴奏、钢琴分离）
4. 音高检测（frame-level pitch activation）
5. Onset/Offset 边界检测
6. 音符后处理（时值合并、去毛刺、量化）
7. 生成 MIDI（tempo map + note events）

## 4. 模型选择建议（免费优先）

### 4.1 免费且实用的开源模型/工具
1. **Basic Pitch（Spotify）**
   - 特点：MIT 开源、易部署、对流行音乐友好。
   - 输出：MIDI + pitch bend。
   - 适合：MVP 首选。

2. **Onsets and Frames（Magenta 系）**
   - 特点：钢琴转录经典方案。
   - 适合：钢琴独奏较强。

3. **CREPE / pYIN（单音高）**
   - 特点：适合旋律线提取。
   - 适合：人声或独奏乐器。

4. **Demucs（分离）**
   - 特点：先做人声/伴奏分离，再分别扒谱可提高精度。

### 4.2 免费 API 选项（现实情况）
严格“完全免费且稳定商用”的在线 API 很少。建议分两类：

- **A. 真免费开源自部署（推荐）**
  - 你自己部署 Basic Pitch / Onsets and Frames，调用本地 API。
  - 优点：真正可控、长期成本低、无限调用。

- **B. 平台试用额度（非长期免费）**
  - 部分云 ASR/音频 AI 平台有赠送额度，但长期通常收费。
  - 适合 PoC，不建议作为长期核心依赖。

> 结论：如果你要“免费可长期用”，最佳路线是“开源模型 + 自建 API”。

## 5. 准确度做到 70%~80% 的关键策略

1. **分场景模型路由**
   - 检测输入是“钢琴独奏/人声主导/全混音”，自动切模型。

2. **先分离再转录**
   - 对混音先 Demucs 分 stem，再对主 stem 转 MIDI。

3. **节拍约束后处理**
   - 用 BPM 网格约束 onset/offset，减少“抖动音符”。

4. **置信度阈值可调**
   - 提供“保守/平衡/激进”三档，用户可在召回率与精确率间取舍。

5. **人机协同编辑**
   - 自动结果 + 快速修正工具，整体可用性远高于“纯自动”。

6. **建立你的测试曲库**
   - 至少 200 首，按风格分桶，持续评估并微调。

## 6. 评估指标与验收

### 6.1 指标
- Note Precision / Recall / F1（onset ±50ms, pitch 正确）
- Note-with-offset F1（更严格）
- Frame-level F1
- 节拍误差（BPM MAE）

### 6.2 业务验收线（建议）
- 旋律模式：Note F1 ≥ 0.80
- 钢琴模式：Note F1 ≥ 0.75
- 混音模式：Note F1 ≥ 0.70
- 单首 3 分钟音频处理时延 ≤ 30s（中端 GPU）

## 7. MVP（4~6 周）实施计划

### 第 1 周：基础框架
- 搭建前端上传页 + 任务页
- FastAPI 服务 + ffmpeg 预处理

### 第 2 周：核心转录
- 接入 Basic Pitch 推理
- 生成 MIDI 并可下载

### 第 3 周：结果可视化
- 波形 + Piano Roll
- 简单编辑（删音、移音、量化）

### 第 4 周：精度增强
- 接入 Demucs 分离（可选开关）
- 增加阈值与量化策略

### 第 5~6 周：优化与发布
- 缓存与并发
- 打包桌面版（Electron）或部署 Web 版
- 基准测试报告

## 8. 你可以直接用的免费技术栈（推荐组合）

- 前端：React + Tailwind + wavesurfer.js
- 后端：FastAPI
- AI：Basic Pitch + Demucs + librosa
- 音频工具：ffmpeg
- 导出：pretty_midi / mido
- 部署：
  - 本地：Docker Compose
  - 云端：1 台带 NVIDIA T4 的机器（预算可控）

---

## 9. 风险与规避

1. **复杂编曲精度不稳定**
   - 规避：先做“旋律/钢琴”强场景，逐步扩展。

2. **在线 API 成本不可控**
   - 规避：核心模型必须可离线自部署。

3. **用户期望过高（100% 自动）**
   - 规避：UI 明确“AI 初稿 + 快速修谱”。

---

## 10. 最小可行接口（示例）

- `POST /api/transcribe`
  - 入参：音频文件、模式、阈值
  - 出参：任务 ID

- `GET /api/tasks/{id}`
  - 出参：状态、进度、日志

- `GET /api/tasks/{id}/result`
  - 出参：MIDI 下载链接、JSON 音符数组
